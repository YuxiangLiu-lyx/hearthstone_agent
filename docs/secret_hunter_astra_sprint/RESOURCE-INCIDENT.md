# 运行中资源条件变化

本轮没有修改用户的前台应用、系统调度或任何候选代码。以下只记录实测执行条件，不使用胜负来决定资源处置。

DA2 独立确认开始后，本机前台负载上升，完整 CLI 吞吐从先前约 50–57 局/分钟下降。检查时该批已有 267 局：7,863 次 Python 决策的 P95 为 0.886 秒、P99 为 1.183 秒、最大 1.612 秒，零超 2 秒、故障回退及策略错误。随后暂停控制器派发，让 6 个在途结果全部持久化，再停止控制器；273 个已完成 DARCL2 任务全部保留，没有丢弃或重跑，也没有读取这批胜负。

使用早先登记的 8 个开发压力局面复测：当前单并发、三并发、六并发的动作逐个一致，全部合法、零回退、零超 2 秒。但其中 4 个动作与资源变化前的原记录不同。基线配置的 `plan_cache` 为 false，完整搜索元数据也已保留；节点数由约 3,362–5,381 降为约 1,343–2,262，两个回合搜索出现时间截断，四个原 `chance_endpoint` 决策改为原排序或回合搜索结果。这是正常时间保护下的搜索变化，不能混写成非法动作或故障回退，也不能忽略它对不同资源时期比较的影响。

两个新的完整 CLI 资源试跑各 24 局，来源种子仍属于登记的 pilot 分区；胜负不参与策略选择。
